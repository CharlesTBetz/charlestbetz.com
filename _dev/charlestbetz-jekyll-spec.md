# charlestbetz.com — Jekyll Site Specification

A specification for migrating Charles T. Betz's composer site from Wix to Jekyll on GitHub Pages. Written to be handed directly to Claude Code or Cowork for implementation.

---

## 1. Project summary

**Owner:** Charles T. Betz — composer, lyricist, arranger, writer
**Tagline:** *Telling stories with music, in a universe of simultaneous time*
**Current site:** https://www.charlestbetz.com (Wix)
**Target:** Jekyll site hosted on GitHub Pages, custom domain pointing to the same `charlestbetz.com`

**Design direction:** Playful & Editorial. A site that reads as a person with taste and voice, not a corporate template. Aimed at a general audience of musical theater and choral fans.

**Featured project on homepage:** *Five Minutes On The Low Road* (musical in development, librettist Josiah Thomas Turner, near-death-experience subject matter).

**Aesthetic shorthand:**
- Editorial typography (display serif + clean sans body)
- Single accent color: deep ink blue
- Generous whitespace, but warmth in the writing
- Voice in section titles ("What I'm working on" rather than "Projects")
- Sparing use of color and ornament — restraint is the design

---

## 2. Tech stack

- **Generator:** Jekyll (latest, currently 4.x). Ruby gem-based.
- **Hosting:** GitHub Pages, deployed via GitHub Actions (so we can use any plugin, not just the GH Pages allowlist).
- **Domain:** `charlestbetz.com` via CNAME file + DNS update at registrar.
- **Email signup:** Buttondown embed (free tier; recommended over Mailchimp for simplicity). Placeholder embed in the spec; real form ID added at deploy.
- **Comments:** None initially. Can add giscus (GitHub Discussions-backed) later if desired.
- **Analytics:** Plausible (recommended, privacy-respecting, lightweight) or none. Optional.
- **No JavaScript framework.** Plain HTML/CSS with one tiny vanilla JS file for the mobile nav toggle.

## 4. Site structure & navigation

**Top-level pages (in nav order):**

1. **Home** (`/`) — wordmark, tagline, featured project block, latest news strip, a short "About" teaser, email signup
2. **Shows** (`/shows/`) — list of musical theater works. Currently just *Five Minutes On The Low Road*.
3. **Pieces** (`/pieces/`) — choral works and standalone songs. Currently *River Song*, *Wild and Precious*, *Earth Was The Dream*, plus older pieces as content allows.
4. **Writing** (`/writing/`) — blog index. Migrated posts.
5. **About** (`/about/`) — full bio, photo, training, what Charles is drawn to, links.
6. **Contact** (`/contact/`) — email, social links, email-list signup.

**Footer:** smaller versions of the same nav, plus social icons (Bluesky, Instagram, LinkedIn, YouTube), a copyright line, and "Site built with Jekyll" credit (optional).

The existing Wix nav clutter (HOME archive, MORE SONGS, COMPOSITIONS-that-points-to-news) is dropped. Old URLs that mattered should redirect — see §11 (Migration).

## 8. Design system

### 8.1 Color

Single accent. Deep ink blue: `#1a2f4a`. Slightly warmer than pure navy, reads as confident and editorial without being corporate.

```scss
// _variables.scss
$color-ink: #1a1a1a;          // body text
$color-ink-soft: #4a4a4a;     // secondary text
$color-muted: #8a8a8a;        // tertiary / metadata
$color-rule: #d8d6cc;         // hairlines, dividers
$color-bg: #fafaf7;           // page background, very warm off-white
$color-bg-soft: #f4f1e8;      // cards, blockquote, callouts
$color-accent: #1a2f4a;       // ink blue — links, wordmark, key emphasis
$color-accent-hover: #2c4a73; // hover state
```

Usage rules:
- Body text: `$color-ink` on `$color-bg`
- Links: `$color-accent`, with a subtle underline (1px, offset 3px). On hover, color shifts to `$color-accent-hover` and underline thickens.
- Section labels (small uppercase metadata): `$color-muted`
- Section dividers: 1px solid `$color-rule`, used sparingly
- The accent appears in: links, the wordmark in the header, the active nav item underline, the email signup submit button background, blockquote left border. Nothing else. The point of an accent is restraint.

### 8.2 Typography

Two families, both Google Fonts (free, no licensing concerns):

- **Fraunces** — display serif for headlines, the wordmark, and large pull quotes. Has optical sizes and slight quirks; reads as editorial without being academic.
- **Inter** — for body, navigation, metadata, UI. Workhorse sans-serif.

Load only the weights you use. Recommended:
- Fraunces: 400, 500, 600 (with optical size axis)
- Inter: 400, 500, 600

```scss
// In head.html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Fraunces:opsz,wght@9..144,400;9..144,500;9..144,600&family=Inter:wght@400;500;600&display=swap" rel="stylesheet">
```

```scss
// _typography.scss
$font-display: "Fraunces", "Iowan Old Style", Georgia, serif;
$font-body: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;

body {
  font-family: $font-body;
  font-size: 18px;
  line-height: 1.6;
  color: $color-ink;
  background: $color-bg;
  -webkit-font-smoothing: antialiased;
  text-rendering: optimizeLegibility;
}

h1, h2, h3, h4 {
  font-family: $font-display;
  font-weight: 500;
  line-height: 1.15;
  letter-spacing: -0.01em;
  color: $color-ink;
  margin-top: 0;
}

h1 { font-size: clamp(2.4rem, 5vw, 3.6rem); font-weight: 400; }
h2 { font-size: clamp(1.8rem, 3.5vw, 2.4rem); }
h3 { font-size: 1.4rem; }
h4 { font-size: 1.1rem; }

// Editorial details:
// - Headlines can use italic (Fraunces has a beautiful italic) for emphasis
// - Use Fraunces "soft" optical setting for body display, "normal" for headlines

// Small caps / metadata labels
.label {
  font-family: $font-body;
  font-size: 0.78rem;
  letter-spacing: 0.14em;
  text-transform: uppercase;
  color: $color-muted;
  font-weight: 500;
}

// Pull quote / tagline
.tagline {
  font-family: $font-display;
  font-style: italic;
  font-weight: 400;
  font-size: clamp(1.4rem, 2.5vw, 1.9rem);
  line-height: 1.3;
  color: $color-ink-soft;
}

// Body links
a {
  color: $color-accent;
  text-decoration: underline;
  text-decoration-thickness: 1px;
  text-underline-offset: 3px;
  transition: color 0.15s ease;
  &:hover { color: $color-accent-hover; text-decoration-thickness: 2px; }
}
```

### 8.4 Components

**Featured project block (homepage):**
- Large display headline (Fraunces italic) with the show title
- A logline below in body sans
- Status badge ("In development") in small caps
- Hero image (16:9 or 3:2)
- Single CTA: "Read about the show →" linking to the show page
- Background: subtle `$color-bg-soft`, generous padding, no border

**News strip (homepage):**
- Section label: "Latest"
- 4–6 most recent items as a vertical list, each with a date in monospace small-caps and a one-sentence description with an inline link
- "More news →" link at the bottom

**Audio/Video embeds:**
- YouTube embedded with `youtube-embed.html` include — uses the privacy-friendly `youtube-nocookie.com` domain, lazy-loaded
- Audio (if hosted) uses the native `<audio controls>` element, styled minimally

**Email signup (footer of home, also dedicated section on /contact/):**
- Section label: "Stay in touch"
- One-line description: "Occasional updates on new work and performances."
- Email input + "Subscribe" button (button uses `$color-accent`)
- Buttondown form action

**Show card / Piece card (used on /shows/ and /pieces/ index pages):**
- Title in Fraunces, status/year as small-caps metadata, logline in body
- Optional thumbnail (1:1 or 3:2) on the left at desktop, top on mobile
- Whole card is clickable

## 9. Page-by-page specification

### 9.1 Home (`index.html`, layout: `home`)

**Structure top to bottom:**

1. **Site header** (wordmark + nav, shared via `header.html`)
2. **Hero section**
   - Eyebrow label: "Composer · Lyricist · Arranger · Writer"
   - Tagline as the visual hero: *"Telling stories with music, in a universe of simultaneous time"* — set large in Fraunces italic
   - Brief 1–2 sentence intro sentence below in body sans (e.g., "Based in Minneapolis. I write musical theater and choral music.")
3. **Featured project block** — *Five Minutes On The Low Road*. Pulled automatically from the show with `featured: true`. (See §8.4.)
4. **Latest** strip — pulls the 5 most recent posts and/or hand-curated news items from `_data/news.yml` (see §9.7 alternative).
5. **What I'm working on** — short section with 2–3 paragraphs of current activity. Hand-edited in `index.html` or pulled from `_data/now.yml` so it can be updated without touching layouts.
6. **Recent piece** — featured piece block with one of the choral works (manually selected via `featured: true` on the piece). Single embed (YouTube via include) and a few sentences.
7. **About teaser** — one paragraph of bio + portrait + "Read more →" link to /about/.
8. **Email signup**
9. **Footer**

### 9.2 Shows index (`pages/shows.md`)

- Page title: "Shows"
- Optional one-line intro: "Musical theater works, in development and beyond."
- Loop over `site.shows` sorted by `order`, render each as a Show Card.
- Currently only one card. Empty-state-friendly: even with one show, the layout looks intentional.

### 9.3 Show detail (`_layouts/show.html`)

For each item in `_shows/`:

- Eyebrow label: "A musical" + status (e.g., "In development")
- H1: show title in Fraunces, large
- Logline as a tagline pull quote
- Hero image (full width within the narrow container)
- Two-column metadata strip below the hero on desktop: collaborators on the left, status notes on the right
- Synopsis section
- Free-form body content (this is where the songs/embeds live)
- "More from this project" — pulls posts where `related_show: <slug>` matches
- Footer link: "Back to Shows"

### 9.4 Pieces index (`pages/pieces.md`)

- Page title: "Pieces"
- One-line intro: "Choral works and standalone songs."
- Loop over `site.pieces`, sorted by `year` descending
- Optional filter at top: "All / Choral / Songs" (achievable with a tiny vanilla JS filter, or skip and just group by `kind` server-side)
- Each piece rendered as a Piece Card

### 9.5 Piece detail (`_layouts/piece.html`)

- Eyebrow: kind + voicing + duration (e.g., "Choral · SATB choir, piano · 8 min")
- H1: piece title
- Year + premiere details below the title
- Primary embed (first item in `recordings`)
- Free-form body
- Recordings list (all recordings in front matter, including the primary)
- Performance history (table or list, oldest first or newest first — newest first is more useful)
- Score inquiry CTA if `score_inquiry: true` — mailto link with subject pre-filled
- "Back to Pieces" link

### 9.6 Writing index (`pages/writing.md`)

- Title: "Writing"
- One-line intro: "Notes from the desk. Process, performances, and what I'm thinking about."
- Paginated list of posts (10 per page)
- Each entry: date, title (linked), excerpt, optional related-piece tag

### 9.7 News data file (alternative or addition to posts)

For homepage news strip and the `/news/` archive (if migrating), consider `_data/news.yml`:

```yaml
- date: 2025-08-01
  text: 'Check out "Earth Was The Dream!" — sung by Lia Peros — final version for now after much refinement.'
```

### 9.8 About (`pages/about.md`)

- Title: "About"
- Portrait photo (left or top)
- First-person bio in body. Migrate from current Wix /bio page; cut the third-person AI-emerging-composer language if it's there.
- Training & honors section: Nautilus Composer-Librettist Studio, NMI "From Outline to Draft" with John Sparks, IANDS field research, etc.
- "What I'm drawn to" — a short section in your voice about themes and aesthetics (near-death experience, simultaneity, the Mississippi, spirituality)
- Links out: social, Bluesky, Instagram, LinkedIn, YouTube
- Email contact (or push to /contact/)

### 9.9 Contact (`pages/contact.md`)

- Title: "Contact"
- Email (mailto link, or use a contact form via Formspree/Buttondown — recommend mailto for simplicity)
- "I'm interested in:" short list — performances, score inquiries, collaborations, press
- Social links
- Email signup form

### 9.10 404 (`404.html`)

A real 404 page with voice. Title: "Page not found." Body: a short note ("The page you wanted isn't here. Maybe it was renamed when I moved off Wix. Try one of these:") plus links to home, shows, pieces, writing.

## 11. Migration plan (from Wix)

Wix doesn't offer a clean export, so the migration is mostly manual but well-bounded. The plan:

### 11.1 Inventory the existing site

Before writing any markdown, capture every URL on the current Wix site that has unique content. From the homepage nav, that's:
- `/` (home)
- `/copy-of-home` (HOME archive — old news; may be skippable or partial)
- `/shows`
- `/music` (SONGS)
- `/copy-of-songs` (MORE SONGS)
- `/news` (COMPOSITIONS)
- `/gallery`
- `/bio`
- `/contact`
- `/blog` and every individual blog post URL

For each, save the page as HTML or copy the relevant text into a working document.

### 11.2 Content mapping

| Wix page                                 | New home                                  |
|------------------------------------------|-------------------------------------------|
| `/` (home)                               | `/` (rebuilt from scratch using spec)    |
| `/shows`                                 | `/shows/` index                           |
| `/music`, `/copy-of-songs`               | `/pieces/` (merged, deduped)              |
| `/news`                                  | Mix of `_posts/` (substantive items) and `_data/news.yml` (one-liners), plus homepage Latest strip |
| `/gallery`                               | Embedded into relevant show/piece pages, or a dedicated `/gallery/` page if there's enough imagery to justify it |
| `/bio`                                   | `/about/`                                 |
| `/contact`                               | `/contact/`                               |
| `/blog/<slug>`                           | `/writing/YYYY/MM/<slug>/`                |
| `/copy-of-home`                          | Drop. The valuable news items get migrated as posts or news entries. |

### 11.3 Blog post extraction

For each post on `/blog/`:
1. Open the post in a browser
2. Use the browser's "Reader Mode" or copy the article text
3. Paste into a new file `_posts/YYYY-MM-DD-slug.md`
4. Add front matter (layout, title, date, excerpt, tags)
5. Convert Wix's HTML formatting to Markdown — most posts will have light formatting (paragraphs, occasional bold/italic, a few links and images)
6. Re-host any images: download from Wix's CDN, upload to `assets/images/posts/<slug>/`, update `<img>` tags to `![alt](/assets/images/posts/<slug>/file.jpg)`
7. Verify the final post renders cleanly

A semi-automated approach worth trying first: tools like `wix-to-markdown` or running each post URL through a service like `urltomarkdown.herokuapp.com` will produce a draft Markdown that needs cleanup. Faster than from scratch but always needs a human pass.

### 11.4 Redirects

Use `jekyll-redirect-from` to preserve old URLs. In any post or page that's replacing an old Wix URL, add to front matter:

```yaml
redirect_from:
  - /post/old-slug-from-wix
  - /post/another-old-url
```

This generates HTML pages at the old URLs that 302 to the new URL — preserves links from elsewhere on the web, search results, social media references.

### 11.5 Image migration

- Audit all images currently on Wix CDN (URLs like `https://static.wixstatic.com/...`)
- Download originals (Wix's URLs sometimes include resize parameters; strip them to get the original)
- Re-upload to `assets/images/` with a sensible directory structure
- Compress: use `cwebp` or `sharp-cli` to produce `.webp` versions; keep `.jpg` as fallback if needed. For a small site, even just well-compressed JPEGs at 1600px wide max are fine.
- Don't link to Wix CDN from the new site. The migration's whole point is independence.

### 11.6 Email-list continuity

If there's an existing Wix email list with subscribers, export the list (Wix → Marketing → Subscribers → Export) before tearing the Wix site down. Import to Buttondown. Send one announcement from Buttondown so subscribers know the new home.

### 11.7 DNS cutover

This is the only step where order matters and timing is delicate.

1. Build the Jekyll site, deploy to GitHub Pages, verify it works at `<username>.github.io/charlestbetz-site`.
2. Add a `CNAME` file containing `www.charlestbetz.com` to the repo root. Configure custom domain in GitHub Pages settings.
3. At the domain registrar (whoever currently hosts the DNS — could be Wix, could be a separate registrar), update DNS:
   - `A` records for the apex `charlestbetz.com` pointing to GitHub Pages IPs:
     - `185.199.108.153`
     - `185.199.109.153`
     - `185.199.110.153`
     - `185.199.111.153`
   - `CNAME` record for `www` pointing to `<username>.github.io`
4. Wait for DNS propagation (15 min – 24 hours typically).
5. In GitHub Pages settings, enable "Enforce HTTPS" once the cert is provisioned (can take an hour or two after DNS resolves).
6. Test: `https://charlestbetz.com` and `https://www.charlestbetz.com` both serve the new site, with HTTPS, and old `/post/` URLs redirect to `/writing/...` paths.
7. Cancel the Wix subscription (only after DNS is verified working for at least a few days).

**Important:** keep the Wix site live until DNS is confirmed pointing to GitHub Pages. Don't cancel Wix first.

## 12. Deployment (`.github/workflows/deploy.yml`)

Use GitHub Actions instead of GitHub's classic Pages build, so we're not limited to the Pages plugin allowlist.

```yaml
name: Build and deploy Jekyll site

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.2'
          bundler-cache: true
      - name: Build with Jekyll
        run: bundle exec jekyll build
        env:
          JEKYLL_ENV: production
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./_site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

In repo settings → Pages → Source, choose "GitHub Actions."

## 14. Accessibility

- Semantic HTML throughout (`<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`)
- Skip-to-content link as the first focusable element
- Color contrast: ink blue `#1a2f4a` on `#fafaf7` is ~12:1, well above WCAG AA. Verify any other color pairings.
- Every image has `alt`. Decorative images use `alt=""`.
- Embeds (YouTube iframes, audio elements) have descriptive `title` attributes.
- Focus styles preserved (don't remove default outlines without replacing them with visible focus rings).
- Heading hierarchy: one `<h1>` per page, no skipping levels.
- Mobile nav button has `aria-expanded` and `aria-controls`.

---

## 15. Performance

- Self-hosted fonts optional; if used, preload the woff2 files. Google Fonts with `display=swap` is fine for v1.
- Compress images (target: hero images ≤ 200KB, thumbnails ≤ 50KB).
- Lazy-load all images and iframes (`loading="lazy"`).
- No third-party scripts beyond the optional analytics.
- Target Lighthouse scores: 95+ across the board on the homepage. Realistic with the spec as written.

## 19. What this spec deliberately omits

- **A theme.** This site is built from scratch rather than starting from Minimal Mistakes or another theme, because the design language is specific and themes always need extensive overriding to match a defined aesthetic. The CSS footprint here is small enough (~400 lines) that owning it is easier than fighting a theme.
- **A CMS.** Editing happens through the GitHub web UI or locally. For a site this size with one author, that's correct. A headless CMS (Decap, Tina) is reasonable to add later if Charles wants a friendlier editing UI, but it's not needed to launch.
- **Search.** Site is small enough that nav + a clear structure makes search unnecessary. Add Pagefind later if the post archive grows large.
- **A newsletter archive page.** Buttondown has its own archive. Link out to it rather than mirroring it.
